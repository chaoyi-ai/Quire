# 侧栏重设计（提案）

日期：2026-09-04（0.6.0 已按此实现：`Sources/Quire/Sidebar/`）。起因：用户反馈"左边的树交互和设计都不太好"。本文先诊断现状，再看同类产品怎么做，最后推出新版本的结构、交互与实现计划。

## 1. 现状诊断

打开 `docs/DESIGN.md` 时的侧栏（0.5.11）自上而下是：

```
docs ⌄                       ← 根目录路径控件
RECENTS                      ← 10 条，来自整个系统的"最近打开"，与本根目录无关
  DESIGN.md / 09_交易心理.md / 5 Daily Habits… / …
TAGS                         ← #anchor #hashtag #issue #rgb #rrggbb #rrggbbaa #tag #标签
  …
research / screenshots       ← 真正的文件树从这里才开始
DESIGN.md
  Quire 设计文档              ← 当前文件的大纲，作为树的子节点嵌在里面
    1. 一句话定位
    2. 目标与非目标
      目标 / 非目标（至少 1.0 之前）
    …（3 级缩进，几十行）
```

问题按严重度：

1. **两种层级混在一棵树里。** 文件树（文件夹 / 文件）和文档大纲（标题）是两个不同的结构，却共用一个 NSOutlineView：展开一个文件就把它的标题当子节点塞进树。后果是缩进深（文件夹 → 文件 → H1 → H2 → H3 = 5 级 × 12 pt）、当前文件一展开就把树撑长几十行、切换文件时树结构跳变、大纲行和文件行长得差不多分不清。而且**每个**文件都能展开出大纲（`headingCache` 按 URL 缓存），用户其实只关心当前这篇。
2. **虚拟分组把树挤走。** 「最近」占 10 行、「标签」占 N 行，都在树上面；打开一个新文件夹，第一屏看到的是别处的文件和一堆标签，而不是这个文件夹。「最近」还是系统级的（`NSDocumentController.recentDocumentURLs`），列的是和当前根目录无关的东西。
3. **标签误报。** 技术文档里 `#rgb`、`#rrggbb`、`#anchor`、`#hashtag` 都被当成标签——它们在行内代码 `` `#anchor` `` 或作为说明文字出现。扫描器跳过了围栏代码块，没跳过行内代码；颜色启发式只挡纯十六进制。结果标签分组在非笔记类目录里几乎全是噪声。
4. **信息密度与视觉。** 12–12.5 pt 字、缩进 12 pt、图标灰色低对比；分组标题是全大写英文（中文界面里也是 RECENTS / TAGS）；没有缩进引导线，深层级看不清归属；当前文件只靠半粗体区分。
5. **搜索 / 筛选入口不明显。** ⌘⇧F 才出现搜索框，平时看不到；搜索时整棵树被结果替换，没有"按名字筛树"这种轻量操作。
6. **缺少常用动作。** 新建文件 / 文件夹、重命名、移到废纸篓、折叠全部、定位当前文件（VS Code 的 Reveal）都没有；右键只有收藏与 Finder。

## 2. 同类产品怎么做

| 产品 | 结构 | 值得借鉴 |
| --- | --- | --- |
| **Typora** | 侧栏三种互斥模式：文件树 / 文章列表 / 大纲，菜单或角落按钮切换；大纲"滚动或编辑时当前章节的标题会在大纲里标出"，可 flat / 可折叠，支持关键字过滤；文件树只显示支持的文件类型；排序：自然 / 字母 / 修改时间 / 创建时间 | 大纲与文件树是两个东西；大纲跟随滚动 |
| **Obsidian** | 文件管理器是一个面板，大纲、标签各是独立面板；文件管理器顶部有"全部展开 / 折叠"、排序、"新建"按钮；"自动定位当前文件"选项；右键：新建、重命名、删除、移动 | 面板头部的一排小动作；定位当前文件；标签是独立面板不是树的一部分 |
| **iA Writer** | Organizer 四段：Locations（多个根）、Favorites、Smart Folders（默认一个 Recents = 全库最近 25 个）、Hashtags；文件列表行显示标题 + 预览 + 日期 | 「最近」是一个"智能文件夹"（一个位置），不是永远摊开在树上面的列表；收藏 / 标签是分段 |
| **VS Code** | 资源管理器 = 上下堆叠的可折叠分段：打开的编辑器 / 文件夹 / 大纲 / 时间线；每段标题悬停出动作（新建文件、折叠全部、刷新）；分段可拖拽调高度、可隐藏；`⌥⌘F` 在树里按名字过滤；大纲默认跟随光标；缩进引导线、sticky scroll | **堆叠分段**这个骨架；段头动作；按名过滤 |
| **Bear** | 侧栏两段：Notes（内置分类）+ Tags；`#a/b` 嵌套标签成树 | 嵌套标签 |
| **macOS HIG** | 侧栏用 source list 样式，13 pt，图标 + 文字，层级要浅，分组标题小号灰字 | 字号与密度 |

共识：**文件树、大纲、标签是三个面板，不是一棵树**；大纲只看当前文档并跟随滚动；「最近」是入口不是常驻列表；面板头部放动作。

## 3. 设计原则

1. **树是树，大纲是大纲。** 侧栏 = 上下两个分段：「文件」和「大纲」，各自一个 NSOutlineView，中间可拖分隔。
2. **默认安静。** 打开一个文件夹第一眼看到的就是这个文件夹。收藏 / 标签折叠在下面，为空不显示；「最近」挪进根目录菜单与 ⌘P。
3. **以当前文档为中心。** 切文档时树自动定位（可关），大纲只显示当前文档并跟随滚动高亮。
4. **动作就在手边。** 分段头部悬停出动作；右键菜单齐全；键盘能走完全部路径。
5. **不做库。** 仍然是"文件夹 + 文件"之上的轻量导航（DESIGN.md 非目标不变）：不做数据库、不做多根同时展示（多根用切换）。

## 4. 新版本

```
┌──────────────────────────────────┐
│ ▣ docs                        ⌄ │  位置栏：根目录名；点开 = 最近打开的根目录 / 打开文件夹… / 在 Finder 中显示
│ 🔍 筛选或搜索…               ⌥⌘F │  常驻筛选框（细）：打字 = 按名筛树；回车 = 全文搜索（结果替换树）
├──────────────────────────────────┤
│ ⌄ 文件                  + ⊟ ◎   │  段头（悬停出动作：新建、折叠全部、定位当前文件）
│   ▸ 📁 research                  │  13 pt，行高 24，缩进 16 + 引导线
│   ▸ 📁 screenshots               │
│     📄 DESIGN                     │  ← 当前文件：source-list 选中态
│     📄 PERFORMANCE                │
│     📄 ROADMAP                    │
│                                  │
│ ═══════ 可拖分隔 ═══════          │
│ ⌄ 大纲 · DESIGN            ⊟ ≡  │  段头（折叠全部 / 平铺·层级切换）
│   1. 一句话定位                   │  只有当前文档的标题；跟随滚动高亮当前章节
│   2. 目标与非目标                 │
│     目标                          │
│     非目标（至少 1.0 之前）        │
│ ▸ 3. 关键技术决策（ADR 摘要）      │  可折叠
│   …                              │
├──────────────────────────────────┤
│ ▸ 收藏 (2)                       │  默认折叠；为空不显示
│ ▸ 标签 (5)                       │  默认折叠；嵌套 #a/b 成树；误报修掉
└──────────────────────────────────┘
```

### 4.1 位置栏

- 显示根目录名 + 图标；点击弹菜单：**最近打开的根目录**（最多 8 个）、打开文件夹…、在 Finder 中显示、（分隔）显示隐藏文件 / 只显示 Markdown。
- 文件级「最近」不再常驻：进 ⌘P（空查询时列最近 25 个，按 iA 的做法）和 文件 → 打开最近使用。

### 4.2 筛选 / 搜索框

- 常驻在位置栏下方，占一行，占位文字「筛选或搜索…」。
- 打字即**按名字筛树**（VS Code 的 filter 模式）：不匹配的文件隐藏，匹配的祖先文件夹自动展开，匹配片段加粗；Esc 清空。
- 回车 = **全文搜索**（现有 `ContentSearch`），结果（文件 → 命中行）替换「文件」段，段头变成「搜索结果 (n)」+ 关闭按钮；大纲段不受影响。

### 4.3 「文件」段

- 只显示 Markdown（含额外扩展名）与文件夹；文件名**不带扩展名**（同名不同扩展时才显示）。
- 行：图标（文件夹 = `folder` 强调色；文件 = `doc.text`）+ 名字；13 pt；行高 24；缩进 16 pt；缩进引导线（细线，跟随 hover 显示）。
- 当前文件：source-list 选中态（系统高亮），不用半粗体；切换文档自动 reveal（设置可关）。
- 段头动作（悬停出现）：**新建文件**（在选中文件夹 / 根下，进入重命名）、**折叠全部**、**定位当前文件**（⌘⇧J）。
- 右键：打开、在新标签页打开、在 Finder 中显示、复制路径、新建文件 / 文件夹、重命名（回车）、移到废纸篓（⌘⌫，`FileManager.trashItem`）、加入 / 移出收藏。
- 排序：自然（默认）/ 名称 / 修改时间；文件夹优先。放在位置栏菜单。
- 键盘：↑↓ 移动，→ 展开 / ← 折叠（文件夹），回车打开，空格 Quick Look，⌘↓ 在 Finder 中显示——沿用现有实现。
- 文件夹旁不显示计数（安静）。
- 拖放：文件拖到文件夹 = 移动（带确认，后续）。

### 4.4 「大纲」段

- 只显示**当前文档**的标题，来自 `session.parsed.outline`（已经有），不再为每个文件扫标题（去掉 `headingCache` 那条路径）。
- 层级用缩进（12 pt / 级），H1 用 medium 字重，其余 regular；可折叠（三角），段头有「平铺 / 层级」切换（Typora 的 flat / collapsible）。
- 跟随滚动：阅读视图当前章节高亮（现有 40% 取样规则），高亮行自动滚入视口；点击跳转（现有）。编辑模式跟随光标所在标题（新增，复用 `lineNumber(at:)` → 标题行）。
- 段头动作：折叠全部 / 展开全部；标题数 > 200 时默认只展开到 H2。
- 空文档 / 没有标题：段内显示一行淡字「没有标题」。
- 两段之间是 NSSplitView（垂直）的分隔，可拖；大纲段可整体折叠（点段头三角），折叠后文件段占满。默认比例 60 / 40。

### 4.5 「收藏」与「标签」段

- 都在最底部，默认折叠，段头显示计数；为空不显示。
- 收藏：文件行同「文件」段样式；右键移出。
- 标签：`#a/b` 按 `/` 嵌套成树（Bear）；点标签 = 筛选框填入 `#tag` 并执行搜索。
- 扫描器修正：跳过行内代码（反引号内）、跳过 URL（`http…#frag`）、跳过标题行、跳过 HTML 实体（已有）、跳过 `#` 后紧跟数字或十六进制的 3/4/6/8 位颜色（已有，改成"全十六进制且长度是 3/4/6/8 **且含数字**"避免 `#face` 之类）。设置里可关闭标签段。

### 4.6 视觉

- 字：13 pt（HIG 侧栏标准），段头 11 pt 小号半粗、灰色、**本地化**（文件 / 大纲 / 收藏 / 标签）。
- 图标：SF Symbols，文件夹用强调色（跟随系统强调色），文件用次要标签色；大小 15 pt。
- 行高 24（文件）/ 22（大纲）。
- 缩进引导线：`separatorColor`，仅在 hover 段内显示。
- 侧栏最小 200、默认 260、最大 480。

### 4.7 键盘与菜单

- `⌥⌘F` 聚焦筛选框（VS Code 同款）；`⌘⇧F` 仍是全文搜索（聚焦并进入搜索态）。
- `⌘⇧J` 定位当前文件；`⌘⌥⇧O`（暂定）切换大纲段折叠。
- 显示菜单增加「侧栏 ▸ 文件 / 大纲 / 收藏 / 标签」勾选项，控制各段显隐（VS Code 的 "…" 菜单）。

## 5. 实现计划

现有 `SidebarViewController`（886 行）里文件树、大纲、分组、搜索、Quick Look、键盘都在一个 NSOutlineView 数据源里。重构成：

1. `SidebarViewController`：容器。位置栏 + 筛选框 + 一个垂直 `NSSplitView`（文件段 / 大纲段）+ 底部固定的收藏 / 标签段（各自小 outline view，折叠时只剩段头）。
2. `SidebarSectionHeader`（新）：段头视图：三角 + 标题 + 计数 + 悬停动作按钮。
3. `FileTreeController`（新，从现有代码抽出）：`SidebarNode(kind: folder/file)` + `listFolder` + FolderWatcher + 筛选（名字匹配 → 隐藏不匹配、展开祖先）+ 搜索态（`ContentSearch` 结果树）+ 右键与文件操作（新建 / 重命名 / 废纸篓：`FileManager`；重命名后 `MarkdownDocument` 的 `fileURL` 跟着走）。
4. `OutlineController`（新）：只吃 `Outline`，跟随 `onSectionChanged`，折叠 / 平铺。
5. 收藏 / 标签：`Favorites`、`TagIndexStore` 不变，`TagScanner` 修误报 + 嵌套。
6. 去掉：`headingCache` 与 per-file 标题扫描、虚拟分组插在根节点前面的 `virtualSections/reinsertSections` 机制、`RECENTS` 段。
7. 偏好：`sidebar.revealCurrent`（默认开）、`sidebar.sections`（各段显隐）、`sidebar.sort`、`sidebar.outlineFlat`。
8. 测试：`TagScannerTests` 加行内代码 / URL / 嵌套；文件筛选的纯函数（匹配 + 祖先展开）单测；大纲跟随的现有测试保留。

工作量估计：2–3 个版本。第一版（结构 + 文件段 + 大纲段 + 去噪）先出，收藏 / 标签细化与文件操作第二版。

## 6. 不做什么

- 不做文章列表模式（Typora 的 Articles）：那是"一个文件夹 = 一本笔记本"的用法，和文件树重复。
- 不做多根同时展示（iA 的多 Locations）：用位置栏切换。
- 不做标签数据库 / 标签重命名。
- 不在侧栏里做预览文字 / 修改日期两行式的行（iA 的列表行）：侧栏是导航，不是列表。
